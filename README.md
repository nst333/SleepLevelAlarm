# Sleep Level Alarm

갤럭시 워치에서 단독으로 실행하는 개인용 수면·기상 실험 앱입니다. 스마트폰과 인터넷 없이 알람을 예약하고, 센서로 수면 진입과 기상 적합도를 추정합니다. 추적 화면에는 AI가 추정한 각성·N1·N2·N3·REM 단계가 표시됩니다.

## 빌드와 실행

- Android Studio, JDK 21, Android SDK 36 / Build Tools, Galaxy Watch4 이후 Wear OS 기기.
- `wear/libs/samsung-health-sensor-api-1.4.1.aar`를 준비합니다. 현재 작업 환경에서는 Downloads에 있던 공식 SDK를 사용했습니다. 새 체크아웃에서는 별도로 받아야 합니다.
- Android Studio에서 프로젝트를 열고 `wear` 구성을 워치에 실행합니다. SDK 경로는 로컬 `local.properties` 또는 `ANDROID_HOME`으로 설정합니다.

```powershell
$env:JAVA_HOME = 'C:\Program Files\Android\Android Studio\jbr'
.\gradlew.bat :core:test :wear:assembleDebug :wear:lintDebug
adb -s <watch-serial> install -r wear/build/outputs/apk/debug/wear-debug.apk
```

APK: `wear/build/outputs/apk/debug/wear-debug.apk`. package: `com.aestus.sleeplevelalarm`. Gradle wrapper 8.14, Android API 30 이상을 대상으로 합니다. 삼성 센서 SDK 개발 모드는 개인 테스트에만 사용하며 배포에는 삼성 승인이 필요합니다.

## 사용법

1. 워치에서 심박·신체 활동 권한과 알람 알림을 허용합니다. 이어 별도 버튼에서 야간 센서 접근(항상 허용)을 허용합니다. 실제 삼성 센서를 쓰려면 Health Sensor Service 개발 모드도 준비합니다.
2. 기상 마감 시각 또는 사이클 횟수를 선택하고, 진동과 소리 / 진동만을 설정합니다.
3. 취침할 때 **수면 시작**을 누릅니다. 최종 알람을 먼저 예약한 뒤 센서 수집을 시작합니다. 센서·야간 접근 권한이나 SDK 연결이 없으면 일반 알람으로 동작합니다. 전체 화면 알람이 차단된 경우 앱의 설정 버튼에서 허용할 수 있습니다.
4. 기상하면 알람을 종료합니다. 수면 추적을 중간에 종료하면 해당 알람도 취소됩니다. 센서 서비스만 중단되면 최종 알람은 유지됩니다.

마감 시각 모드는 직전 30분에 스마트 기상을 시도합니다. 사이클 모드는 수면 진입부터 `90분 × 1~6회`의 전후 15분을 사용합니다. 기본값은 마감 07:00 / 5회 / 소리 켜짐입니다. 사이클 모드의 임시 수면 진입은 시작+15분이며, 최초 30분 안에 감지되면 한 번만 보정합니다. 이후 감지 실패는 알람 시각을 계속 밀지 않습니다.

알람은 5분간 출력하며 종료와 미응답을 기록합니다. 재부팅·시각 변경·앱 업데이트 후 미래의 최종 알람을 복구합니다. 이미 지난 알람은 5분 이내면 복구 실행하고 그보다 오래 지났으면 미실행으로 기록합니다. 활성 세션의 기상 시각은 절대 시각으로 고정하며, 시간대 변경은 표시만 바꿉니다. 시스템 시각을 직접 바꾸면 센서 추적은 중단하고 일반 알람을 유지합니다. 다시 추적하려면 앱에서 재시작합니다.

## 구조와 실험 규칙

- `core`: Android와 분리된 설정·세션 모델, 기상 시간 계산, 30초 구간 특징 계산, 실험 규칙, CSV 재생 도구.
- `wear`: Compose for Wear OS, 삼성 SDK 어댑터, health foreground service, 정확한 OS 알람, 출력 서비스, Room 기록, DataStore 설정.
- 스마트폰 연동은 아직 구현하지 않았습니다. 향후 Data Layer로 설정·기록을 연결하되 활성 알람 실행은 워치가 담당합니다. 서버·계정·통신 의존성은 없습니다.

### AI 수면 단계

`AI/sleep_stage_pipeline.py`의 Conv1D–LSTM을 기존 참가자 분할로 학습한 뒤 LiteRT 모델로 앱에 포함합니다. 30초마다 유효 심박의 평균(bpm)과 중력을 포함한 가속도 크기의 모집단 표준편차(g)를 계산합니다. 연속 30구간이 모이면 마지막 구간의 수면 단계를 표시합니다. 데이터 누락·미착용·지연이 발생하면 입력 창을 다시 채웁니다.

웨어러블 간 성능 차이를 확인하려면 Galaxy Watch와 수면다원검사를 함께 기록한 데이터가 필요합니다. Sleep-Accel의 테스트 참가자 6명에서 정확도는 56.8%, macro F1은 0.427이었습니다. [Olivia Walch, PhysioNet Sleep-Accel v1.0.0](https://physionet.org/content/sleep-accel/1.0.0/)

모델을 다시 만들려면 TensorFlow, pandas, scikit-learn 환경에서 헤더가 있는 Sleep-Accel CSV 폴더를 지정합니다.

```sh
python AI/train_wear_model.py /path/to/walch-apple-watch
```

### 기상 적합도

첫 10개의 유효 구간(약 5분)을 심박 기준선으로 사용합니다. 유효 심박 15개, 가속도 375개, IBI 10개 미만이거나 미착용이면 해당 구간을 추정에서 제외합니다. 연속 5분간 움직임 RMS가 0.015g 미만이고 심박이 기준선의 95% 미만이면 수면 진입 후보로 봅니다. 이후 움직임과 심박 상승이 연속 1분 관찰되면 기상 후보가 됩니다. 마감 모드에서는 예상 90분 경계 10분 이내에 이를 우선하고, 경계 밖에서도 2분의 연속 증거나 마감 전 5분에 기상할 수 있습니다.

이 수치는 **보정 전 초기 실험값**이며 수면과 조용히 누워 있음을 정확히 구별하지 못합니다. IBI는 유효성 검사와 RMSSD 기록에 사용하고, 아직 임상 근거가 없는 HRV 임계값은 적용하지 않습니다. 삼성 SDK의 묶음 IBI 시각은 마지막 측정 시각에서 역산합니다. 새 데이터가 60초보다 오래되면 스마트 기상에서 제외합니다. 데이터 수집·콜백 지연이 크면 일반 알람만 동작할 수 있습니다. 알고리즘 버전은 `rules-v1-uncalibrated`입니다.

수집 중에만 health foreground service를 실행합니다. 센서 추적이 강제 종료되면 자동으로 센서를 켜지 않고 일반 알람을 유지합니다. 알람 출력 서비스는 시스템 재전달 시 남은 출력 시간을 복구합니다. 앱 강제 중지, 권한 회수, 전원 꺼짐, 배터리 방전은 알람을 막을 수 있습니다. 기기의 방해 금지·소리 설정도 실기기에서 확인해야 합니다.

## 기록과 재생

세션 요약은 30일, 원시 센서·구간 특징·추정 결과는 7일 동안 앱 내부에 보관합니다. 세션 시작·복구 시와 매일 OS 정리 작업에서 만료 데이터를 지웁니다. OS가 작업을 지연하면 정리도 지연될 수 있습니다. 앱 백업과 기기 이전에서 수면 데이터는 제외합니다.

**수면 추적을 종료한 뒤** 디버그 APK의 원시 기록을 추출할 수 있습니다. 진행 중인 gzip 파일은 완결되지 않아 추출 도구가 건너뜁니다. 앱이나 알람을 강제 종료하지 않으며 기존 추출 파일을 덮어쓰지 않습니다.

```powershell
python scripts/export_recordings.py --serial <watch-serial> --out exports
.\gradlew.bat -q :core:run --args="exports/<recording>.csv.gz" > exports/replayed.csv
python -m unittest discover -s scripts -p 'test_*.py'
```

원시 기록 열은 `at,receivedAt,heartRate,ibiMs,linearAccelerationG,offBody,heartRateValid`입니다. 시각은 epoch ms, IBI는 ms, 가속도는 중력을 제외한 g 단위입니다. 재생은 수집 지연을 보존하고 실시간과 같은 특징/추정 코드를 사용합니다. Room의 세션 요약과 구간별 지연·특징은 Android Studio Database Inspector로 확인할 수 있습니다.

## 배터리 보호 (0.1.1)

- 화면의 시각·데이터 신선도 갱신은 화면이 보일 때만 30초마다 실행합니다. 화면이 꺼지거나 앱이 가려지면 이 작업을 취소합니다.
- 추적 중 매번 세션을 DB에서 읽는 대신 Room의 변경 알림을 구독합니다. 센서 데이터가 없을 때의 처리 주기는 1초에서 30초로 늘렸습니다. 센서 데이터가 도착하면 바로 처리하며 심박 1Hz·가속도 25Hz의 수집 해상도는 유지합니다.
- 화면 꺼짐 시 심박 묶음 전달이 늦어지는 것을 보완하기 위해 심박 트래커만 최대 30초에 한 번 flush합니다. 가속도에는 강제 flush를 하지 않고, 영구 웨이크록이나 반복 정확 알람을 추가하지 않습니다. 이 주기는 기존 60초 신선도 기준을 위한 초기 절충값이며 실제 야간 배터리 측정이 필요합니다.
- 원시 기록은 버퍼에 모아 30초마다 디스크에 내보내고 정상 종료할 때 남은 데이터를 마무리합니다. 파일 형식·보존 기간은 같습니다. 추적을 재개할 때는 별도 구간 파일을 만들어, 강제 종료로 미완성인 이전 gzip에 새 데이터를 붙이지 않습니다. 강제 종료 시 아직 버퍼에 남은 최신 데이터는 유실될 수 있습니다.
- **충전 중이 아니고 잔량이 20% 이하이면 센서 수집·추정과 추적 서비스를 종료하고 최종 알람만 유지**합니다. 세션 기록과 OS 알람은 취소하지 않습니다. 이 상태에서는 스마트 기상 대신 일반 알람으로 동작하며, 충전 후 앱에서 센서 추적을 다시 시작할 수 있습니다.
- SDK 접근 오류로 수집할 수 없을 때도 추적 서비스를 종료하고 일반 알람을 남깁니다. 기록 정리 작업은 중복 등록을 피하고 배터리가 부족하면 연기합니다.

20%는 초기 보호 기준이며 특정 워치가 기상 시각까지 버틸 것을 보장하는 값이 아닙니다. 실제 배터리 소모는 워치 상태와 다른 앱, 화면 및 무선 디버깅에도 영향을 받습니다. 야간 비교 측정 중에는 앱 확인을 마친 뒤 무선 디버깅을 끄고 평소와 같은 설정으로 비교해야 합니다.

## 검증

```powershell
# 전용 테스트 기기에 활성 알람이 없는 상태에서 실행
$env:ANDROID_SERIAL = '<emulator-or-test-watch-serial>'
.\gradlew.bat :wear:connectedDebugAndroidTest
```

자동 검증은 기상 범위, 자정/DST, 감지 실패·보정 제한, 누락·미착용·중복·지연 입력, 원시 기록 파싱·재생, 실제 OS 알람 발화·중복 방지·취소·복구와 저장 보존을 다룹니다. 에뮬레이터에서는 삼성 센서 수집을 검증할 수 없습니다.

검증 환경은 Wear OS API 36, 480px 원형 에뮬레이터입니다. JVM 테스트 25개, 에뮬레이터 통합 테스트 7개, Python 내보내기 테스트 1개를 실행합니다. 배터리 20% 시뮬레이션은 에뮬레이터에서만 수행하고 종료 시 배터리 상태를 복구합니다. Android Lint의 의존성 최신 버전 안내와 코드 스타일 권고는 남겨 두며 오류는 허용하지 않습니다.

실기기에서 최소 세 번의 8시간 야간 테스트가 남아 있습니다. 같은 워치의 미실행 야간과 비교하여 추가 배터리 소모 15%p 이하, 새 추정 갱신 지연 60초 이내를 초기 목표로 측정해야 합니다. 화면 꺼짐·절전·취침/방해 금지 모드, 프로세스 종료·재부팅, 권한 철회와 미착용도 확인합니다. 이 목표는 아직 달성했다고 주장하지 않습니다. 모델 정확도는 라벨이 있는 별도 검증 데이터로 평가해야 합니다.

스누즈, 반복 알람, 스마트폰 앱, 클라우드, 4단계 수면 분류는 첫 버전에서 제외했습니다.
